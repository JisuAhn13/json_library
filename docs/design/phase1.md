# Phase 1 — 요구사항 정의

## 목표

레코드 단위로 JSON 파일을 관리하는 CRUD 앱의 기능 범위를 명확히 정의한다.

---

## 데이터 모델

JSON 파일은 레코드(record) 배열을 저장한다. 각 레코드는 고유 `id`를 가진다.

```json
[
  {"id": 1, "name": "홍길동", "age": 30, "city": "서울"},
  {"id": 2, "name": "김철수", "age": 25, "city": "부산"}
]
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | integer | 자동 부여, 삭제해도 재사용하지 않음 |
| 나머지 필드 | 자유 | 사용자가 키-값 형태로 자유롭게 입력 |

---

## CRUD 기능 정의

### Create — 새 레코드 저장

- 사용자가 필드명과 값을 반복 입력한다.
- 입력 완료 시 `id`를 자동 부여해 배열에 추가한다.
- `id`는 기존 레코드 중 최댓값 + 1로 생성한다.

**예시 입력:**
```
필드명 > name
값     > 홍길동
필드명 > age
값     > 30
필드명 > (Enter — 입력 완료)
```

**저장 결과:**
```json
{"id": 1, "name": "홍길동", "age": 30}
```

---

### Read — 목록 조회 및 검색

| 기능 | 설명 |
|---|---|
| 전체 목록 | 모든 레코드를 번호와 함께 출력 |
| ID 검색 | 특정 `id` 값으로 레코드 한 건 조회 |
| 키 검색 | 특정 필드명과 값으로 일치하는 레코드 전체 조회 |
| 결과 없음 | "검색 결과가 없습니다." 출력 |

---

### Update — 특정 필드 수정

- `id`로 레코드를 선택한다.
- 수정할 필드명을 입력한다.
- 기존 값을 보여주고 새 값을 입력받아 저장한다.
- `id` 필드는 수정할 수 없다.

---

### Delete — 안전한 레코드 삭제

- `id`로 삭제할 레코드를 선택한다.
- 삭제 전 해당 레코드 내용을 출력하고 확인(y/n)을 받는다.
- 확인 후 배열에서 제거하고 저장한다.
- 삭제 후 남은 레코드의 `id`는 변경하지 않는다.

---

## 값 타입 추론 규칙

사용자 입력은 문자열이므로 저장 전에 타입을 추론한다.

| 입력 예시 | 추론 타입 | 저장 값 |
|---|---|---|
| `홍길동` | string | `"홍길동"` |
| `30` | integer | `30` |
| `3.14` | float | `3.14` |
| `true` / `false` | boolean | `true` / `false` |
| `null` | null | `null` |
| `[1,2,3]` | array | `[1, 2, 3]` |
| `{"a":1}` | object | `{"a": 1}` |

추론 실패 시 문자열로 저장한다.

---

## 제약 조건

- JSON 파일 최상위 구조는 **배열(`[]`)** 이다.
- 각 레코드는 **`id` 필드를 반드시** 가진다.
- 파일 인코딩은 **UTF-8** 고정.
- `id` 필드는 사용자가 직접 수정하거나 입력할 수 없다.
